# Сервер

Хранит состояние лендинга. Лендинг представляет личный бренд эксперта + магазин курсов (эксперт продаёт свои курсы).

Владелец приложения через админку может настраивать расположение блоков в лендинге, менять тексты, контакты, управлять изображениями, создавать карточки курсов, задавать цены и так далее.

Через админку владелец обращается к серверу по паролю. Сброс пароля должен производиться одной командой к контейнеру.

Не должно быть лишних переменных окружения или вольюмов. В этом плане всё, что не является необходимым — лишнее. Владелец не айтишник, ему нет интереса копаться в настройках.

## Реализованный сервер

Один лендинг, один владелец и вход по паролю. Сервер хранит настройки страницы, карточки курсов, изображения, историю сохранений и тестовые заказы. Интерфейсы лендинга и админки разрабатываются в соседних проектах; этот репозиторий предоставляет HTTP API.

Сохранение сразу публикует изменения. Каждое сохранение создаёт отдельную версию; возврат к старой версии создаёт новую, сохраняя историю. Покупка пока имитируется: заказ получает статус `simulated_paid`, деньги не списываются, данные карт и покупателей не запрашиваются. Подключение CRM предусмотрено через отдельный модуль заказов, но интеграции сейчас нет.

## Запуск в Docker

```sh
docker compose up -d --build
docker compose exec server node dist/auth/reset-password.js
```

Вторая команда устанавливает первоначальный пароль и выводит его в терминал. Сохраните пароль. До её выполнения вход в админку недоступен. Эта же команда сбрасывает забытый пароль и немедленно завершает все действующие сеансы, без перезапуска сервера. Пароль не передаётся через переменные окружения и не печатается при обычном запуске.

Сервер слушает `127.0.0.1:3000` на машине с Docker. Лендинг, админка и API должны быть доступны через один HTTPS-домен: обратный прокси направляет `/api/` на сервер и сохраняет исходный заголовок `Host`. Например, внутри настроенного HTTPS-сервера Nginx:

```nginx
location /api/ {
    client_max_body_size 64m;
    proxy_set_header Host $http_host;
    proxy_pass http://127.0.0.1:3000;
}
```

Статические файлы интерфейсов и TLS настраиваются на прокси отдельно. В контейнере авторизационная cookie имеет флаг `Secure`, поэтому вход через обычный HTTP не подходит. Дополнительные обязательные переменные окружения отсутствуют.

Все постоянные данные находятся в SQLite `/app/data/server.sqlite` внутри единственного тома `server-data`. Обычный `docker compose down` сохраняет том; `docker compose down -v` удаляет данные. Обновление сервера: `docker compose up -d --build`. Проверка состояния: `GET /health`.

## Локальная разработка

Требуется Node.js 24.

```sh
npm ci
npm run password:reset
npm run dev
```

Локальная база создаётся в `data/server.sqlite`. Для работы браузерных интерфейсов настройте их dev-прокси `/api` на `http://127.0.0.1:3000`, сохраняя исходный `Host`. Браузер должен обращаться к API через тот же origin, что и страница; отдельный CORS-доступ не предусмотрен.

```sh
npm run typecheck
npm run lint
npm test
npm run build
```

## Данные лендинга

Настройки представлены одним документом: `schemaVersion: 1`, общие поля `site`, массив карточек `courses` и упорядоченный массив `blocks`. Порядок элементов `blocks` определяет порядок отображения. У каждого блока есть уникальный `id`, `type`, `title` и `visible`. Блоки одного типа можно повторять.

| Тип блока | Дополнительные поля |
| --- | --- |
| `hero` | `text`, `imageId`, `action: { label, url }` или `null` |
| `about` | `text`, `imageId` |
| `text` | `text` |
| `courses` | `courseIds` — упорядоченный массив идентификаторов курсов |
| `gallery` | `images: [{ imageId, alt }]` |
| `testimonials` | `items: [{ author, text, imageId }]` |
| `faq` | `items: [{ question, answer }]` |
| `contacts` | `text`; контакты берутся из `site.contacts` |

Поля `imageId` у `hero`, `about`, отзывов и курсов допускают `null`. Остальные поля обязательны. Тексты — обычный текст, интерфейс должен выводить их без интерпретации как HTML. Ссылки принимают HTTP(S)-адрес, путь с `/` или якорь с `#`.

Пример полного документа:

```json
{
  "schemaVersion": 1,
  "site": {
    "title": "Имя эксперта",
    "description": "Практические курсы",
    "contacts": {
      "email": "expert@example.com",
      "phone": "",
      "address": "",
      "links": []
    }
  },
  "courses": [
    {
      "id": "intro",
      "title": "Вводный курс",
      "description": "Описание курса",
      "priceMinor": 99000,
      "currency": "RUB",
      "imageId": null,
      "visible": true
    }
  ],
  "blocks": [
    {
      "id": "welcome",
      "type": "hero",
      "title": "Учимся вместе",
      "text": "Знакомство с экспертом",
      "visible": true,
      "imageId": null,
      "action": { "label": "Курсы", "url": "#catalog" }
    },
    {
      "id": "catalog",
      "type": "courses",
      "title": "Курсы",
      "visible": true,
      "courseIds": ["intro"]
    }
  ]
}
```

Цена `priceMinor` задаётся целым числом в минимальных единицах валюты: `99000` для RUB означает 990 рублей. Начальное состояние пустое. Публичный API исключает скрытые блоки и курсы; административный возвращает полный документ. Скрытие не является ограничением доступа к уже опубликованным изображениям: ссылки `/api/media/:id` публичны.

## HTTP API

JSON-запросы отправляются с `Content-Type: application/json`. После входа браузер использует сеансовую HttpOnly-cookie, срок действия — 7 дней. Для изменения данных проверяется origin запроса. Слишком частые попытки входа и покупки возвращают `429`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/health` | Проверка работоспособности |
| `GET` | `/api/site` | Опубликованный документ |
| `POST` | `/api/auth/login` | Вход: `{ "password": "..." }` |
| `GET` | `/api/auth/session` | Проверка текущего сеанса |
| `POST` | `/api/auth/logout` | Завершение сеанса |
| `GET` | `/api/admin/content` | Полный текущий документ |
| `GET` | `/api/admin/content/schema` | JSON Schema документа для построения и проверки формы админки |
| `PUT` | `/api/admin/content` | Сохранение: `{ "baseRevision": 1, "content": { ... } }` |
| `GET` | `/api/admin/revisions?limit=50&before=10` | История, от новых версий к старым |
| `GET` | `/api/admin/revisions/:id` | Содержимое конкретной версии |
| `POST` | `/api/admin/revisions/:id/restore` | Возврат к версии: `{ "baseRevision": 5 }` |
| `GET` | `/api/admin/backups/current` | Скачать резервную копию текущих настроек |
| `GET` | `/api/admin/backups/:id` | Скачать резервную копию выбранной версии |
| `POST` | `/api/admin/backups/restore` | Импорт: `{ "baseRevision": 5, "backup": { ... } }` |
| `GET` | `/api/admin/media` | Список загруженных изображений |
| `POST` | `/api/admin/media` | Загрузка изображения двоичным телом запроса |
| `DELETE` | `/api/admin/media/:id` | Удаление неиспользуемого изображения |
| `GET` | `/api/media/:id` | Получение изображения |
| `POST` | `/api/checkout` | Тестовая покупка: `{ "courseId": "intro" }` |
| `GET` | `/api/admin/orders?limit=50&offset=0` | Список тестовых заказов |

Все пути `/api/admin/*` требуют авторизации. Чтение и сохранение контента возвращают `{ revision, savedAt, content }`. Для сохранения и восстановления передавайте актуальное значение `revision` в `baseRevision`. Если другая вкладка успела изменить данные, сервер вернёт `409`: нужно заново прочитать документ и согласовать изменения.

При тестовой покупке обязателен заголовок `Idempotency-Key` с UUID. Повторный запрос с тем же ключом и курсом возвращает прежний заказ, а использование ключа для другого курса вызывает `409`. Сервер берёт название, цену и валюту из опубликованной карточки курса, сохраняя их в заказе; последующее изменение карточки не изменяет заказ. Скрытый или отсутствующий курс купить нельзя.

### Изображения

Тело запроса загрузки содержит байты файла, а не `multipart/form-data`. Укажите фактический `Content-Type`: `image/png`, `image/jpeg`, `image/gif` или `image/webp`. В ответе доступны идентификатор и URL изображения. Вставляйте идентификатор в `imageId` документа.

Один файл ограничен 10 MiB. Проверяются сигнатура и базовая структура файла; полное декодирование изображения не выполняется. SVG и видео пока не принимаются. Модуль `media` отделяет работу с файлами от блоков страницы и заказов, чтобы позже добавить видео. Файлы сейчас хранятся в SQLite, одинаковое содержимое получает одинаковый идентификатор.

Изображение, используемое хотя бы одной сохранённой версией, удалить нельзя: иначе возврат к ней стал бы неполным. Неиспользованные загрузки можно удалять через API.

### История и резервные копии

История хранится без автоматической очистки. Восстановление предыдущей версии или импорт файла сразу публикует содержимое и добавляет новую запись в историю.

Резервная копия — JSON-файл с документом выбранной версии и всеми изображениями, на которые он ссылается, включая скрытые элементы. Файл можно скачать и импортировать на новом сервере после установки административного пароля. В копию не входят пароль, сеансы, заказы, другие версии и неиспользуемые изображения. Это переносимая копия настроек страницы; для сохранения всей базы вместе с историей и заказами нужна отдельная копия Docker-тома при остановленном сервере.

Максимальный размер JSON-запроса настроек — 1 MiB; суммарный размер уникальных изображений одной версии — 32 MiB; размер запроса импорта резервной копии — 64 MiB. История и медиа используют место в постоянном томе: скачанные резервные копии следует хранить отдельно от машины с сервером.
